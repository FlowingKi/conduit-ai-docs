El nodo **trigger** es siempre el primer nodo de una automatización. Define qué evento dispara el flow.

## webhook

Se activa cuando el endpoint recibe una llamada HTTP POST.

```
URL: https://conduit-ai-prod.vercel.app/api/webhooks/{automation_id}
Método: POST
```

El payload completo queda disponible como `{{trigger._payload}}` en todos los nodos siguientes.

**Casos de uso típicos:** notificaciones de GitHub, formularios externos, integraciones custom.

<Card title="Cómo configurar un webhook" icon="webhook" href="/guides/configure-webhook">
  Ver guía paso a paso para conectar un webhook real.
</Card>

## schedule

Se activa según una expresión cron. El bridge ejecuta el flow en el horario definido.

```
# Todos los lunes a las 9:00
0 9 * * 1

# Cada hora
0 * * * *

# Cada día a las 00:00
0 0 * * *
```

**Casos de uso típicos:** resúmenes diarios, reportes semanales, limpieza periódica de datos.

## manual

Solo se activa cuando el usuario hace clic en **▶ Run** en la interfaz. No tiene trigger automático.

Útil para flows que se quieren ejecutar on-demand con un botón, o para testear un flow antes de configurar un trigger real.

## service_event ⚠️ pendiente de revisión

<Warning>
Este tipo de trigger funciona técnicamente pero está pendiente de revisión de UX y documentación más detallada. Lo que sigue documenta el comportamiento actual.
</Warning>

Se activa cuando un servicio conectado via Composio genera un evento (ej: nuevo issue en GitHub, nuevo mensaje en Slack).

**Cómo funciona internamente:**
1. Composio detecta el evento en el servicio externo
2. Lo escribe en la tabla `trigger_events` de Supabase
3. El bridge lo recibe via Supabase Realtime
4. Busca automatizaciones activas cuyo trigger node tenga el mismo `service` + `event`
5. Ejecuta el flow con el payload del evento

**Configuración en el nodo trigger:**
- `service` — el slug del servicio (ej: `github`, `slack`)
- `event` — el tipo de evento (ej: `pull_request_opened`, `message_received`)

**Pendiente de revisar:**
- Qué eventos están realmente disponibles por servicio
- Cómo mejorar la UI de configuración del nodo trigger para este tipo
- Documentar el formato del payload por servicio

| Tipo | Trigger automático | Requiere bridge corriendo |
|------|--------------------|--------------------------|
| `webhook` | Sí — evento externo | Sí |
| `schedule` | Sí — cron | Sí |
| `manual` | No — usuario hace clic | No |
| `service_event` | Sí — evento Composio | Sí |
