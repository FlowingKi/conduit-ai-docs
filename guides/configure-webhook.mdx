---
title: Configurar un webhook
description: Cómo recibir datos externos en una automatización usando un trigger de webhook.
---

Un webhook te permite que sistemas externos (GitHub, Typeform, tu propia API, etc.) disparen una automatización enviando un `POST` a una URL de Conduit AI.

## Cómo funciona

Cuando creás una automatización con trigger de tipo **Webhook**, Conduit AI genera una URL única:

```
https://conduit-ai-prod.vercel.app/api/webhooks/{webhook_id}
```

Cualquier `POST` a esa URL con un body JSON activa la automatización. El payload queda disponible en todos los nodos del flow como `{{trigger._payload}}`.

---

## Paso 1 — Crear la automatización con trigger Webhook

1. Abrí un workspace y andá a la pestaña **Canvas**
2. Hacé clic en **Nueva automatización**
3. En el panel del nodo **Trigger**, elegí el tipo **Webhook**
4. Guardá — la URL del webhook aparece en el panel del trigger

Copiá la URL. Tiene el formato:
```
https://conduit-ai-prod.vercel.app/api/webhooks/abc123xyz
```

---

## Paso 2 — Probar con curl

Enviá un payload de prueba desde la terminal:

```bash
curl -X POST https://conduit-ai-prod.vercel.app/api/webhooks/abc123xyz \
  -H "Content-Type: application/json" \
  -d '{"nombre": "Juan", "mensaje": "Hola desde curl"}'
```

Si la automatización está activa, el bridge recibe el payload y ejecuta el flow.

---

## Paso 3 — Usar el payload en los nodos

El payload completo está disponible como `{{trigger._payload}}`. Para acceder a campos específicos:

```
{{trigger._payload.nombre}}     → "Juan"
{{trigger._payload.mensaje}}    → "Hola desde curl"
```

Podés usar estas variables en cualquier nodo: Agent, Instruction, Condition, Tool, etc.

**Ejemplo en un nodo Instruction:**
```
Redactá una respuesta para {{trigger._payload.nombre}}.
Su mensaje fue: {{trigger._payload.mensaje}}
```

---

## Paso 4 — Configurar el sistema externo

Pegá la URL en el sistema que quieras conectar:

| Sistema | Dónde configurar |
|---------|-----------------|
| GitHub | Settings → Webhooks → Add webhook |
| Typeform | Connect → Webhooks |
| Stripe | Developers → Webhooks |
| Tu API | Donde hagas el POST al completar un evento |

El sistema externo enviará el payload automáticamente cada vez que ocurra el evento configurado.

---

## Formato del payload

El webhook acepta cualquier JSON válido. Si el body no es JSON, se guarda como `{ "raw": "..." }`.

```json
// Ejemplo de payload de GitHub (PR mergeado)
{
  "action": "closed",
  "pull_request": {
    "merged": true,
    "title": "Fix: corrección de bug en auth",
    "user": { "login": "juan" }
  }
}
```

Accedés a campos anidados con dot notation:
```
{{trigger._payload.pull_request.title}}
{{trigger._payload.pull_request.user.login}}
```

---

## Respuesta del endpoint

El webhook responde inmediatamente con `{ "ok": true }` — no espera que el flow termine. La automatización se ejecuta en background.

Si la automatización está inactiva o la URL no existe, responde `404`.

---

## Notas

- La automatización debe estar en estado **activo** para recibir webhooks
- El bridge debe estar corriendo para que el flow se ejecute
- Cada automatización tiene su propia URL — no se comparten entre flows
